# CSteroid — Agent Guide

CSteroid is a .NET source-generator library (Interface-First Model Generation):
from C# interfaces decorated with `[CanonicalModel]` it generates partial model
classes, mapping code, and validation. Generators use Roslyn
`IIncrementalGenerator`; core and generator libraries target `netstandard2.0`,
the Blazor adapter targets `net8.0`/`net10.0`, and tests target `net10.0`.
Solution file: `src/CSteroid/CSteroid.slnx`.

## Build & Test

```bash
dotnet build src/CSteroid/CSteroid.slnx
dotnet test  src/CSteroid/CSteroid.slnx
dotnet build examples/Examples.slnx
# Pack a generator package (same pattern for all CSteroid.Generator.* projects):
dotnet pack src/CSteroid/CSteroid.Generator.EFCore/CSteroid.Generator.EFCore.csproj -c Release
```

## Layout (src/CSteroid/)

- `CSteroid.Core` — public API: attributes, enums, `IMapper<TSource,TDest>`, validation engine
- `CSteroid.Blazor` — `EditContext` integration for custom validation
- `CSteroid.Orm` — `OrmTarget` flags enum + attribute
- `CSteroid.Generator` — base model generator
- `CSteroid.Generator.Mapping`, `.Validation` — mapping / validation generators
- `CSteroid.Generator.EFCore|.Dapper|.CosmosDB|.MongoDB|.PostgreSQL` — one full-model generator per ORM target
- `CSteroid.Generator.Shared` — shared generator internals (build-time only, not packable)
- `CSteroid.Generator.Testing` + `*.Tests` — shared xUnit harness and one test project per generator
- `CSteroid.Blazor.Tests` — bUnit tests for `EditContext` integration
- `CSteroid.Benchmarks` — BenchmarkDotNet suite (mapping vs Mapperly, validation vs hand-written)
- `../examples/HexagonalDdd` — metadata-lib DDD sample: interfaces in metadata projects, each layer project generates only the namespaces it claims via `GeneratorConfig.GenerateOnlyNamespaces`

## Rules

- Use the `code-graph-rag` MCP server for "where is X defined/used" before broad repo scans.
- Do not change attribute constructor signatures — they are the public API.
- Core and generators compile against `netstandard2.0`; modern framework targets belong in dedicated adapters such as `CSteroid.Blazor`.
- Keep generator output deterministic: sort collections with `StringComparer.Ordinal`.
- Generated classes are `partial` intentionally; generated files start with `// <auto-generated />`.
- Style: 4-space indent, classic block namespaces, usings outside the namespace.
